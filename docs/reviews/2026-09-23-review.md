# 2026-09-23 Whole-Tree Bug, Design and Incomplete-Feature Review

## Scope and method

- **Baseline:** main `f6340ea`.
- **Method:** six parallel read-only reviewers, one per domain (core/indexing,
  server/cli/config, mcp/search, parser, analysis/git) plus one cross-cutting
  audit of advertised-versus-implemented behaviour. Each finding was checked
  against source at HEAD or reproduced with the release binary on a scratch
  fixture. Items already fixed by the 2026-09-03 campaign were excluded; items
  still open from `2026-09-08-skill-mapping-findings.md` are marked
  `(open since 09-08)`.
- **Personally re-verified by the coordinator:** IDX-1, IDX-6, PAR-1, SRV-1,
  SRV-2, MCP-1.
- Finding IDs are stable. Task bodies cite them as `2026-09-23-review.md#<ID>`.

## Cross-cutting themes

1. **Watch mode and `/reindex` diverge from a fresh index.** Imports, side
   effects, reference stats, directory deletes and truncated files all drift
   after incremental updates (IDX-1..IDX-9, MCP-3).
2. **Call-graph resolution is weak outside Go.** C++ qualified calls, typed
   parameters, member-field receivers and constructors do not resolve, so
   reach, dead-code, callers and purity are wrong for most non-Go code
   (PAR-2..PAR-10, ANA-1).
3. **Advertised surface without a reader.** Flags, schema parameters and
   config keys are accepted and ignored; several outputs are placeholders
   (INC-*).

## Findings

### Indexing and core (IDX)

- **IDX-1 (high)** `src/core/import_resolver.cpp:84` —
  `build_import_graph` clears `import_graph_` and rebuilds from the files
  queued since the last pass. The watch path (`master_index.cpp:494`,
  `reparse_file_symbols`) queues one file, so one save wipes every other
  file's import bindings; watch and fresh index then resolve differently.
- **IDX-2 (high)** `src/indexing/pipeline_processor.cpp:246-251` — `/reindex`
  merges side-effect results into the live `McpRuntime::side_effects` under a
  processor-private mutex while MCP handlers (`runtime.cpp:66`,
  `handlers_side_effects`) iterate `results()` unlocked. Concurrent rehash is
  UB. A cancelled reindex has already merged partial results.
- **IDX-3 (med)** `pipeline_processor.h:102-104`, `cli/server.cpp:372-379` —
  `process_single` passes a null side-effect sink and `McpRuntime::warmup`
  runs once, so purity/labels never refresh after edits or `/reindex`;
  propagator labels stay keyed to dead monotonic symbol ids.
- **IDX-4 (med)** `src/indexing/watcher.cpp:216-222,325-335` — a directory
  Remove is documented as prefix invalidation but `apply_path` does an exact
  `path_to_id` lookup; every file under a deleted directory stays indexed.
- **IDX-5 (med)** `master_index.cpp:566,569`, `watcher.cpp:229-233` —
  `update_file` returns early for empty or oversize content without removing
  the old file; truncated or oversize files keep serving stale content.
- **IDX-6 (med)** `src/mcp/runtime.cpp:85` vs `semantic_annotator.cpp:117` —
  annotations are stored under a synthetic `file<<32|line<<16|column` key
  typed `SymbolID` but looked up by the real symbol id, so `@lci:` labels
  never seed the propagator. Related: ANA-3.
- **IDX-7 (med)** `pipeline_integrator.cpp:136-139`,
  `file_content_store.cpp:219-266` — the content store evicts (LRU,
  `max_memory_mb` 500) before integration reads content for imports and
  minified/generated classification; evicted files silently read empty.
- **IDX-8 (med, perf)** `reference_tracker.cpp:482-485` — outside the bulk
  window each write deep-copies the whole Snapshot; one watched edit copies it
  about four times and rebuilds every edge (`process_all_references`) while
  holding `bulk_mu_`.
- **IDX-9 (med)** `debounced_rebuilder.cpp:24-26` — every event pushes the
  deadline out by 300 ms with no max wait; a continuously written file starves
  all pending edits.
- **IDX-10 (low-med)** `reference_tracker.cpp:545-548`,
  `reference_tracker.h:711-716` — `field_types_` is keyed by bare type name,
  last writer wins, never erased by `clear()` or `remove_file`, and written
  outside `write_snapshot` despite its comment.
- **IDX-11 (low)** `file_content_store.cpp:323-324,361-362` — the last line of
  a newline-terminated file keeps `\n` (and CRLF keeps `\r\n`).
- **IDX-12 (low)** `context_lookup.h:32-38` — `max_context_depth` is set by
  the handler and read by nothing in `src/core`.
- **IDX-13 (low)** Dead code: `TrigramIndex::find_candidates*`,
  `index_file_with_trigrams`, `predict_trigram_count`, `force_cleanup`,
  `get_invalidation_count`, `file_count`; `SymbolStore::get_entry_points`,
  `get_top_symbols`; `GraphPropagator::set_config`. Stale comment
  `master_index.cpp:705` ("mmap-retained content").
- **IDX-14 (low-med, open since 09-08)** `DeletedFileTracker` is write-only.
  Watcher loads `.gitignore` once (`watcher.cpp:66`) and lacks the scanner's
  hidden-dir and binary-extension checks (`pipeline_scanner.cpp:164-172,288`).

### Parser (PAR)

- **PAR-1 (high)** `unified_extractor_symbols.cpp:1118-1139` — the complexity
  visitor also matches anonymous keyword tokens named `if`/`for`/`while`, so a
  one-`if` function scores 3 in every grammar that emits them. The comment
  claiming only Ruby emits those names is false.
- **PAR-2 (high)** `unified_extractor_references.cpp:176` — C++ receiver
  typing works only for `T x;` locals: parameters are not seeded, `ns::T` and
  `auto` are not stripped (`go_bare_type`), and unqualified calls to sibling
  methods inside `Widget::compute` stay unresolved.
- **PAR-3 (high)** C++ namespace-qualified calls (`util::helper()`) never
  resolve; dead-code lists `ascii_lower` (40 call lines) and `gmtime_utc`.
  `::open(...)` in `mmap.h:124` resolves to `MmapFile::open` and shows as a
  self-recursion cycle.
- **PAR-4 (high)** member-field receivers (`this.f.m()`) resolve only in Go:
  `field_types_` is written only by Go paths (`_symbols.cpp:537`,
  `_references.cpp:480`). See IDX-10.
- **PAR-5 (high)** `unified_extractor.cpp:695,912` — TS
  `abstract_class_declaration` and `internal_module` are not dispatched; the
  fixture produces a fabricated caller edge to another class's method.
- **PAR-6 (med)** typed parameters not seeded: Kotlin (`_references.cpp:1307`),
  PHP (`:1171`), Python `typed_default_parameter`; Rust `&mut T` and path types
  mis-stripped; Java `var` typed as "var".
- **PAR-7 (med)** `is_function_node` (`unified_extractor.cpp:557`) lacks Java/C#
  `constructor_declaration`, Kotlin init/secondary constructors, Ruby
  `singleton_method`: no complexity, no side-effect context.
- **PAR-8 (med)** `_side_effects.cpp:127` — C/C++ parameters never registered
  (the parameter list is under `declarator`), so parameter writes report as
  `global_write`. Live: `param_writes=0 global_writes=781` on this repo.
- **PAR-9 (med)** `_side_effects.cpp:428` — `++`/`--` recorded as writes only
  in JS/TS/Go; C/C++, Java, C#, Kotlin, PHP, Ruby `+=` missed.
- **PAR-10 (med)** `_side_effects.cpp:483-491` — Java `method_invocation` and
  C# `invocation_expression` missing from the call-node list; unqualified
  calls skipped.
- **PAR-11 (med)** complexity misses Python `elif_clause`/`boolean_operator`,
  Rust `match_arm`, Java/JS/C# switch cases, Kotlin `when_entry`, C#/PHP
  `foreach_statement`.
- **PAR-12 (med)** symbol kinds never extracted: C typedef; Rust
  `type`/`const`/`static`/`union`/`macro_rules!`/trait method signatures;
  Kotlin properties, `typealias`, companion object; C# file-scoped namespace;
  Python module/class assignments; Ruby constants, `attr_accessor`.
- **PAR-13 (low-med)** the same field write is `global_write` (C#, C++, Java,
  Kotlin, Ruby `@x`), `param_write` (Python `self.x`) or `receiver_write`
  (TS, Rust, PHP).
- **PAR-14 (low, open since 09-08)** C++ out-of-class members are kind
  Function named `Widget::compute`; `lci def compute` finds nothing.
- **PAR-15 (low, open since 08-30)** arity is a preference only; C++ `find`
  with 3 args binds to a user `find(int)`.
- **PAR-16 (low)** `parser.cpp:36` — `.tsx` check is case-sensitive while the
  language table is not; `.TSX` gets the non-JSX grammar.
- **PAR-17 (low)** Zig `enum`/`opaque` open no scope; `go_bare_type`
  duplicated (`unified_extractor.cpp:26`, `_references.cpp:73`); Go
  `func_literal` emitted as a nameless Function.

- **SRV-3 (high)** `src/cli/mcp.cpp:35-63` — the MCP bridge binds one `Client`

- **SRV-5 (med)** `src/server/server.cpp:167-177` — the socket hash uses

- **SRV-6 (med)** `src/cli/cli_core.cpp:50-51,81-93` — no project-root
