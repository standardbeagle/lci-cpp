## Root-cause clusters

1. **Index lifecycle:** bulk reindex publishes cleared snapshots before
   opening the bulk window; the incremental (watch) path shipped unwired;
   mmap retention turns in-place truncation into SIGBUS.
2. **Advertised-but-unimplemented parameters/flags/CLI options** that
   return silent zero or no-op (karpathy principle #6).
3. **Hash-order truncation** at ~10 sites (karpathy principle #4).

Two earlier fix rounds (`4cb59b9`, `d3dfe3a`) each missed one call site.

### Domain: core/indexing

**S0 — Purge unreachable index subsystems and archive the review** (this
slice). ~900 LOC of subsystems with zero production callers live inside
hot-path headers: `ShardedTrigramStorage`/`search_trigram`
(`include/lci/core/trigram.h`), `TrigramMergerPipeline` (merges into its own
`storage_` nothing reads), `SlabAllocator` (`get_allocator()` unused),
`TrigramPredictor`, the `BucketedTrigramResult` carried in every
`ProcessedFile`, `CompactFormatter`. Also: the UTF-8 decoder in
`trigram.cpp:14-50` skips invalid lead bytes while
`compute_byte_offsets_into` (`:94-102`) does not, so
`code_points[i]`/`byte_offsets[i]` desync and a Latin-1 `0xC0-0xEF` byte
swallows following ASCII: `TrigramBloom::build` omits real trigrams and
`Narrowing::certifies_absent` certifies a present substring absent.

**S1 — Reindex opens the bulk window before clearing; cancel is not
completion; symbol ids never alias.** Verified: `master_index.cpp:163-170`
clears before `set_bulk_indexing(true)`; each clear publishes an empty RCU
snapshot immediately, so the live server answers "symbol not found" for the
whole reindex. Second: after `request_stop` the partially drained buffer is
still integrated, published, and `index_directory` returns true — a
cancelled reindex is indistinguishable from a complete one. Third:
`reference_tracker.cpp:516` `clear()` resets `next_symbol_id_=1` while
FileIDs were made monotonic for exactly this aliasing reason. Fourth: no
RAII on `is_indexing_`/the bulk window, so an exception mid-scan leaves
`is_indexing_=1` forever.

**Follow-up (filed from S1 review): /reindex still blanks the index.**
`server_endpoints.cpp:341` (`handle_reindex`) calls `indexer_->clear()` on
the line immediately before `indexer_->index_directory(root_path)`,
re-introducing the S1 defect one level up on the HTTP path; `server.cpp:455`
(first boot) does not pre-clear — the asymmetry is the tell.

**S3 — Wire the watch path into the server and fix its three latent
defects (D1).** `watch_mode` defaults true, but FileWatcher,
DebouncedRebuilder, DeletedFileTracker and
`MasterIndex::index_file/update_file/remove_file` have zero callers outside
tests; only `index_directory` is wired. The unwired path is also wrong:
(a) `reference_tracker.cpp:755-767` `remove_file` never zeroes
`target_symbol` on inbound refs from other files, so cross-file references
dangle forever and `call_resolution_totals` counts them as resolved;
(b) `trigram.cpp:582-642` `index_file` erases the file from
`invalidated_files` without purging old locations, so each `update_file`
appends the full trigram set again; (c) `pipeline_integrator.cpp:141` drops
references/scopes/imports of symbol-less files, and same-FileID
re-integration skips `remove_stale_data`, duplicating symbols and trigram
locations.

**S14 — Core perf: O(1) same-name bucket updates and swap-pop postings
removal.** `symbol_store.cpp:33-50,204-226` — `set()` on an existing id does
a linear `erase(remove())` over `symbols_by_name_[name]`; `apply_enrichment`
re-sets every symbol, so bulk cost is quadratic on the serial integrator
thread. `postings.cpp:187-198,233-240` — per-token middle `vec.erase(it)` on
posting vectors when removing/reindexing a file. `symbol_store.cpp:283-285`
— fallback synthetic id `(line<<32)|(column<<16)|i` can collide with real
sequential SymbolIDs.

**Deferred (need a ceiling measurement first):**
`pipeline.cpp:134-185` whole-corpus buffer before integration (H37);
`context_lookup_semantic.cpp:101-121` per-request name-BFS (item 16 core).

### Domain: server/dispatch

**S2 — Content store copy at index time (D2).** (Slice body not in the
surviving source; per D2 the content store copies bytes into anonymous heap
at index time and drops mmap retention, closing the `mmap.h:146`
`MAP_PRIVATE`-retention SIGBUS class. Landed as commit `a9bf1ac`.)

**Follow-up (filed by S2 implementer): pipeline reads the
`batch_load_from_disk` failure list instead of dropping it.**
`pipeline.cpp:90` lets the new failure out-parameter default to nullptr, so
per-file load failures are still dropped and an indexing run over a corpus
with unreadable files reports success.

**Follow-up (filed by S2 review panel): RssAnon self-cap rests on a
premise S2 deleted.** `server.cpp:97-101` justifies the cap with "since the
content store retains file-backed mmaps" — false as of `a9bf1ac`; copied
bytes are anonymous and DO count toward RssAnon (~1x corpus against
`max_rss_mb=4096`). Measured: self-repo server RssAnon 172.8 MB -> 282.8 MB
(+110 MB, +63.7%, 3 warm runs each side).

**S4 — One shutdown gate, bounded /mcp queue, validated /reindex,
lock-free read handlers.** Verified: `server_endpoints.cpp:266` bare
`svr_.stop()` bypasses `stop_listener_once()` (third call site of the same
race). `/shutdown` never fires `self_stop_cb_`, so an evicted `lci mcp`
host stops listening but keeps the full index resident.
`server.cpp:346-355` `start()` does not reset `shutdown_triggered_`.
`/reindex` path is client-controlled, unvalidated against root; a
nonexistent path yields an empty engine with `ready:true`. `/mcp` blocks on
an unbounded `WarmupLatch::wait` with `max_queued_requests_=0`: >=8 bridge
calls during indexing mute `/ping` and `/shutdown`. `require_ready`
releases `mu_` before the handler re-acquires it and `clear()` runs outside
the lock. Wrong-typed JSON bodies throw into httplib -> 500 with empty
body. Socket: chmod after bind; `.lock` opened without `O_NOFOLLOW`; 500ms
readiness poll then `join()` hangs if bind is slow.

### Domain: mcp handlers + search

**S5 — Search flags/scoring.** (Slice body not in the surviving source.
Planner-verified finding: `handlers_search.cpp:406-407` — `nc`/`iv` flags
parsed and never read. S5 landed the `line_is_comment_only` comment
predicate fix, commit `9dd23af`, and the shared-predicate census, commit
`b801774`.)

**Follow-up (filed by S5 implementer): CLI comment filter deletes real
code lines.** `grep_filters.cpp:410` — a line is classified comment-only if
`*/` appears ANYWHERE in it, silently dropping `int x = 1; /* note */` and
`std::string s = "*/";` — data loss in user-facing output. The CLI copy is
a duplicated predicate; the fix unifies both paths on ONE function.

**Follow-up (filed from that unification's review gate): a THIRD copy in
`ast_filters`.** `match_is_in_comment` (`ast_filters.cpp:245`) is
language-UNGATED on `#`; counted: 2,345 lines under `src/`+`include/` open
with `#` and all are code — every one a deletable row on that path.

**Follow-up (user decision 2026-09-04): retain comment spans from the
parse** so comment filtering stops guessing lexically. The parse already
knows which byte spans are comments and the index throws that knowledge
away (`unified_extractor_symbols.cpp:61` visits comment nodes only to skip
them; ExtractionResults carries no comment ranges; the TSTree is freed at
end of parse; no query-time re-parse exists). Measurement: of the 25 lines
in this repo whose trimmed form starts with `*`, ALL 25 are code.

**S6 — Explore and side-effects handlers.** `path_matches_glob` supports
only equality/basename/suffix while the schema advertises globs, so
`file=src/*.ts` silently empties `list_symbols` and `browse_file` answers
`found=false`. `browse_file` basename lookup takes the first hit in
hash order — a different file per process. `max_depth` and `show_imports`
are accepted and unread. Side-effect file/pure/impure/category modes
iterate a `flat_hash_map` and stop at `max_results` with no sort — a
different subset per process. Empty analyzer `results()` fabricates
`total_functions` with `pure_count=total` (100% purity invented).

**S7 — Analysis/context handlers.** `classify_same_name_calls` scans every
reference per call — O(candidates x all refs), quadratic on large corpora.
`languages`, `tier`, `metrics`, `focus` advertised and never read. LCF
header `tokens=` is hardcoded. `append=true` swallows every manifest load
error and overwrites the manifest. Token budget checked only on the next
iteration; `apply_expansions` hydrates then discards expansions. Nine
`get_context` params have no reader. Unknown-param guard only runs when
`arguments.is_object()`. `initialized_` is a bare bool written from two
threads. Batch (array) requests answer "Method not found" instead of
-32600.

### Domain: parser

**S8 — Extractor routes by language_info, restores the local type env on
nested-function exit, guards recursion depth.** Verified:
`unified_extractor_references.cpp:592-598` (JS; also :726 Python, :1000
Rust, :1091 PHP, :1215 Kotlin, :1363 Zig) — entering any nested
function/arrow/closure does `local_var_types_.clear()` and never restores
on exit, so later `param.method()` in the outer body loses its receiver
type. Dispatch compares raw `ext_ == ".js"` while grammar selection is
case-insensitive `language_info` (`.mjs .cjs .pyi .hh` etc. parse and emit
symbols but zero references/type relations/side effects). `visit_node`
recursion has no depth guard — a long `a+b+...` chain overflows the indexer
thread's stack. `in_class_body_` spans the whole class subtree (nested
Python def -> Method). Two C++ declarator peels diverged. `handled_nodes_`
cleared only in `reset()`, not `init()`. Catch-site `detail.resize(57)`
cuts inside a UTF-8 sequence. `local_var_types_.find(std::string(recv))`
allocates per call site.

### Domain: analysis/git

**S10 — Git parsing.** Diff prefix handling strips only `b/`, never passes
`--no-prefix`, never unquotes `core.quotePath`: with `diff.mnemonicPrefix`
or a non-ASCII filename the `+++` path never matches the `-z` name-status
path and the report silently shows zero symbols. `--format=%H|%an|...`
split on `|` breaks on an author name containing `|`. `file_pattern` is
expanded via `ls-files` into argv — a large repo overflows `ARG_MAX`; git
pathspec supports globs natively. `--since` formatted in UTC without `Z`,
parsed by git in local time. Commit branch lacks `--root`; hardcoded SHA-1
empty-tree hash breaks SHA-256 repos. Sorts feeding `resize(max_findings)`
have no tiebreak — which duplicates survive varies per run.
`SymbolInfo.is_pure`/`side_effects` never filled so the PurityLost check is
dead. `subprocess.cpp:192-199` `pipe()` without `O_CLOEXEC` — concurrent
`run_capture` leaks the write end into the other child and the read blocks
until the unrelated child exits.

**S11 — Analyzers.** Callee classification by bare prefix makes JS
`querySelector` a database call, `login` a log call, etc., amplified across
the purity chain. Fixpoint iterates in hash order and `kMaxIterations=100`
truncates silently. Results keyed `file:start_line:0` so multiple functions
on one line overwrite each other. `naming_analyzer.cpp:135` stack buffers
`int prev[64]` with unbounded token length. `high_complexity_funcs` takes
the first 10 in file order, not the top 10. Layer/module keyword matching
by substring (`ui` in `build`, `test` in `latest`). Brandes sigma is `int`
(overflow on layered-diamond DAGs). And more (see slice body).

### Domain: cli/config

**S12 — CLI.** Verified: `cli/server.cpp:173-178` spawn argv carries only
`--root` — global flags silently ignored. No `.lci.kdl` in cwd ->
`ensure_server_running` spawns a server that indexes the whole cwd
(reproduced: `lci search` from /tmp indexed /tmp). Column base disagreement
(server 0-based vs CLI 1-based) — `-w` off by one byte, `--json` column
base differs between `-E` and literal rows. Pure-meta regex full-scan path
ignores `scoped_paths`, `--exclude`, content filters and `--max-count` and
always prints raw JSON. Any token starting with `-` is an exclusion, so
`->next` needs `--`. Alternation branches with no >=3-char literal are
silently dropped from `-E` results. `symbols --file <glob>` and search
post-filters cap at a hard 500 server page. Multiple silent no-op flags.

**S13 — gitignore anchoring parity with git; config load never
terminates.** A non-anchored pattern with an interior slash is
suffix-matched at any depth; git anchors it to the .gitignore directory, so
`x/doc/a.txt` is wrongly ignored — real sources vanish from the index.
Directory-pattern branch ignores `pat.absolute`; wildcard directory
patterns never match files inside. Only the root `.gitignore` is read.
`fs::weakly_canonical` without `error_code` throws out of `load_config` ->
`std::terminate` on an unreadable path component. Numbers go through
`static_cast<int>(double)` — out-of-range wraps and validates. A stray
top-level `}` silently ends parsing of the rest of `.lci.kdl`.
